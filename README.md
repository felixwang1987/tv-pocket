# 影视口袋

和「发票口袋」一样，是可直接打开、放到 GitHub Pages 的自用 HTML 小工具。

支持：四类线路入口、搜索、多仓/线路合集/单配置/直播筛选、一键复制、当前浏览器收藏、JSON 清单导出。只读取配置与播放列表，不执行来源中的插件代码。

## 先打开看看

双击 **index.html**。页面已内嵌一份真实采集快照，不依赖服务器或安装软件。

直播列表会抽检视频画面；多仓、线路合集和单配置标记为「配置可读 · 需实播」。抽检出画面不代表整份列表都能播放，也不保证不同地区或运营商网络可以访问。

首页四类分别是「点播合集」「已抽检出画面的直播」「需影视仓验证的点播与原始配置」「需影视仓验证的直播列表与单流」。点播合集提供「普通点播」与「成人点播」。当前「普通点播」保留小虎斑原配置的普通、网盘与插件线路，并补充通过画面抽检的标准接口，放在同一配置中搜索；保留的原线路只确认配置可读，搜索、登录与播放仍需电视验证。后两类包含原始配置、插件、加密或尚未逐个抽检的内容；加密且无法判断内部内容的配置单独标记「内容类型未知」。原始配置或列表可能含有已进入前两类合集的部分线路，但整份内容不因此视为通过。

## 推荐：发布后每天自动找新链接

1. 在 GitHub 创建一个 **Public** 仓库，例如 `tv-pocket`，默认分支用 `main`。
2. 解压完整发布包，把**文件夹里面的内容**放到仓库根目录，确保根目录直接能看到 `index.html`、`scripts`、`data`、`tests`、`sources.config.json`。
3. 确认仓库还有 **`.github/workflows/update.yml`**。它是定时更新的关键文件。Mac Finder 按 **Command + Shift + .** 显示隐藏文件夹再上传。也可以在 GitHub 的 **Add file → Create new file** 中输入这个完整路径，粘贴本包同名文件的内容。
4. 打开仓库 **Settings → Pages**，在 **Build and deployment → Source** 选择 **GitHub Actions**。
5. 打开 **Actions → 更新影视口袋 → Run workflow → Run workflow**。等 `collect` 和 `deploy` 都变成绿色。
6. 回到 **Settings → Pages** 打开网站地址。之后每天约在 10:23 UTC 自动更新（美西夏令时 03:23、冬令时 02:23）；GitHub 定时任务可能排队延迟，也可在 Actions 手动运行。

普通项目地址形如 `https://你的用户名.github.io/tv-pocket/`。这个自用网页的访问地址是公开的，收藏仅保存在本机浏览器。

工作流使用 GitHub 自动提供的 `GITHUB_TOKEN`，无需把密码或令牌填入 HTML。

**重要：不要把 ZIP 压缩包本身直接上传当网站，也不要把所有文件多套一层目录。**

## 如果只想上传一个 HTML

把 `index.html` 上传到仓库根目录，然后在 **Settings → Pages** 选择 **Deploy from a branch → main → / (root) → Save**。这样可以使用搜索、筛选、复制、收藏和导出，但只是该文件附带的快照，不会在后台发现新链接。之后可以再补齐自动更新文件。

## 日常使用

- **复制点播合集**：复制 `checked/routes.json`，放入影视仓的线路合集入口，选择「普通点播」。刷新配置后，在搜索范围重新全选来源，让新增的普通与网盘线路参与搜索。网页分别显示保留的原站点数、声明支持搜索数及标准接口抽检结果；备用原配置的可读数量不代表全部已合入。
- **成人点播密码**：当前影视仓 6.2.5 不支持点播入口的电视端密码。「成人点播」保留为独立分类，尚未加锁；不能把它视为密码保护的入口。
- **使用网盘会员**：在影视仓选择「普通点播」，按原配置提供的账号设置或扫码入口登录自己的会员；入口名称及支持的网盘依来源插件而定。能否播放取决于账号权限、分享状态和客户端插件支持。不要把账号、密码、Cookie 或 token 填入本网页、来源表单或 GitHub。
- **复制直播合集**：首页按钮会复制 `checked/live.txt` 的线上地址，直接放入影视仓「直播配置」。通过抽检的频道分为「普通直播」和「成人直播」；成人分组使用影视仓 6.2.5 支持的 TXT 原生分组密码。以前导入 `checked/live.m3u` 的，请换成这个 TXT 地址；该版本的 M3U 解析不会弹出分组密码框。只收录近 36 小时成功解码画面的频道，按地址去重。
- **查看待验证来源**：首页第三、第四类分别打开点播配置与直播来源目录。这里的链接需要在你的影视仓和网络环境中尝试，不能因为配置可读就当作已播出画面。
- **检测明细**：展开卡片可看每个抽检频道的结果、原因和检测时间。多仓显示下级配置的可读情况，不假定点播可用。
- **复制地址**：到影视仓对应的多仓、配置或直播入口粘贴；入口名称依软件版本不同。
- **收藏**：点卡片右上角星星，底部「我的收藏」集中显示。同一浏览器刷新仍保留，不跨设备同步。
- **读取最新**：读取已经发布的检查结果。它不会触发 GitHub 采集；想立即采集，到 Actions 手动运行。
- **添加来源**：在网页填写公开直链或收集网页、普通/成人分类，点「去 GitHub 确认提交」。GitHub 会打开预填好的 Issue 表单；用仓库所有者账号确认后立即排队运行检查和部署，不用等第二天的定时任务。提交内容公开可见，勿填写账号、token 或私密链接。首次检查失败的直链会在来源目录显示原因；标准接口与直播须通过画面抽检，原配置合入需在维护配置中明确指定，规则见下文。其他可读原配置留作备用。
- **查看添加结果**：GitHub 会在你提交的 Issue 下回复已接受、已存在或未通过校验。已接受会在同一轮运行采集与 Pages 部署；如本轮检查失败，原有网页和导入地址继续可用，可从回复里的 Actions 链接看原因。
- **手动重新检查**：已有来源想提前复查，可打开仓库的 Actions →「更新影视口袋」→「Run workflow」。网页「读取最新」只读取上次已发布的结果，不启动检查。
- **导出当前列表**：下载当前搜索/筛选结果的 JSON 清单，便于备份和检查；不是通用播放器配置文件。
- 超过 **36 小时**没有检查的数据显示「待重新检查」。请求失败的旧记录仍保留，并显示失败状态。

## 自动采集做了什么

从 GitHub 仓库搜索发现相关公开项目，也读取 `sources.config.json` 指定的公开外部页面与直连配置。目前外部来源包括用户提供的 GYCK 线路合集和奇奇电话论坛帖子；论坛只解析正文中公开列出的地址，普通收集网页只提取静态可见的相关配置/直播链接，不执行网页脚本。点播和直播 GitHub 搜索结果轮流取用仓库名额，候选链接按 URL 去重并保留来源。每天最多扫描 40 个仓库、30 个指定外部页面、检查 360 个候选，其中给线路合集的下级配置预留 40 个检查名额；每仓库最多读取 8 个相关文件，配置文件限 3 MB、单次请求超时 12 秒。网页单页最多读取 500 KB、等待 10 秒，通用网页最多提取 30 条相关链接。它不穷尽搜索整个互联网，外部页面也可能失效或改版。

识别：`storeHouse` 多仓、`urls` 线路合集、`sites` 单配置、M3U 播放列表、HLS 流、直播 TXT。JSON 注释和尾逗号可以解析，但不保证所有播放器都支持非标准 JSON。无法读取的加密配置和未知结构不会自动导出。采集器不执行 JAR／JS 插件；所选原配置按合入模式保留站点及插件上下文，把相对地址转成来源下的完整地址，交给影视仓加载和登录。

初始快照来自 2026-09-23（America/Los_Angeles）的真实运行：17 条，扫描 14 个仓库、检查 113 个候选。由于本机代理 DNS，初次仅检查四个固定 GitHub 域名；其中一个仓库发现过程连接失败，页面已有提示。上传后 Actions 使用正常公共地址校验，会继续尝试第三方域名。数量与可访问性会随上游变化。

## 常见问题

**Actions 的保存快照步骤提示权限不足**：检查 Settings → Actions → General → Workflow permissions 是否允许仓库工作流写入。组织策略或分支保护也可能禁止机器人提交；此时需要仓库管理员允许该工作流写入，或使用自己的独立仓库。

**部署失败**：先确认 Pages 的 Source 是 GitHub Actions，再重新运行。不要同时启用分支部署和本工作流部署。

**长时间不更新**：查看 Actions 最近一次运行。公共仓库连续 60 天没有活动时 GitHub 可能停用定时任务，需要在 Actions 重新启用。本工作流每轮保存检查快照，但仍应以页面时间和 Actions 状态为准。

**全部来源失败**：不会删除旧清单；检查网络、GitHub API 限流和 Actions 日志后重跑。配置检查结果与播放结果分别判断。

**要多收录几个仓库**：编辑 `sources.config.json` 的 `repositories`。公开直链或收集网页可直接用网站的「添加来源」表单；如果网站需登录或靠脚本动态显示链接，仍需单独适配。已有链接按 URL 去重。网页只负责预填 GitHub Issue，未在 GitHub 确认提交时不会改变每日检查配置。

## 本地维护（可选）

需要 Python 3.9 或更高版本，以及 FFmpeg。Python 无第三方依赖；GitHub Actions 会检查并安装 FFmpeg：

```sh
python3 -m unittest discover -s tests -v
python3 scripts/collector.py
python3 scripts/build.py --site
```

本机若使用代理的 Fake-IP DNS，可加 `--github-only`，此模式只允许四个固定 GitHub HTTPS 域名，不检查第三方域名，也不运行实播抽检。Actions 不需要这个参数。普通模式拒绝私有/本地地址，并在重定向时重新检查目标；请在 GitHub 托管 runner 或隔离环境运行第三方来源采集。

`data/sources.json` 保存结构化数据；`index.html` 内嵌同一份数据；`checked/live.txt` 是网页推荐的直播合集，成人分组可在影视仓 6.2.5 使用原生密码；`checked/live.m3u` 保留兼容地址，但不提供此版本的分组密码；`checked/routes.json` 是统一点播线路合集，引用 `checked/vod-all.json`（所选原配置的普通、网盘与插件线路，以及补充的标准接口共用同一 `sites` 列表）和 `checked/vod-adult.json`；`data/cloud-sites.json` 保存所选来源的站点与插件上下文快照；`checked/vod/*.json` 保留旧单站地址兼容，但不再列入合集或提供网页复制入口；`data/routes.json` 保存点播检查明细；`_site/` 是生成的发布目录。工作流只发布网页与清单，不发布脚本或设计文档。

## 验证范围

交付前验证解析、去重、失败保留、私有地址拒绝、HTML 安全内嵌，并检查页面主要操作与响应布局。GitHub Actions 的真实定时和 Pages 部署需要在上传启用后验证。每轮最多抽检 80 份直播列表，普通列表每份 6 个频道，明确标为成人的列表最多 24 个频道，样本每天轮换。HTTP 成功还必须下载视频数据并解码出一帧才计入通过；总抽检时限约 12 分钟、最多 1400 次请求。加密、特殊请求头、分段字节范围、非 HTTP(S) 和非 80/443 端口目前归为需客户端验证。多仓/线路合集最多抽查 24 份、每份 3 个下级文件，单配置不执行 JAR/JS，不验证网盘登录或会员权限。

官方参考：[GitHub Pages 自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)、[GitHub 定时任务](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)、[GitHub 仓库搜索 API](https://docs.github.com/en/rest/search/search#search-repositories)。

## 电视端成人分组密码

直播原生密码由 `sources.config.json` 的 `adult_live_pin` 设置，构建时写入 `checked/live.txt` 的成人分组。影视仓 6.2.5 支持 TXT／JSON 直播分组的 `组名_密码` 格式，M3U 不走这个密码解析流程，因此旧直播地址需要换成网页新复制的 TXT 地址。这个密码用于客户端分组提示，不是服务器访问控制；公开仓库和 TXT 清单仍可读取。

影视仓 6.2.5 的点播配置不支持电视端入口密码，添加密码字段、名称后缀或加密外壳也不会让该版本弹出点播密码框。「成人点播」仍是独立分类，未加电视端密码。

## 点播合集检查范围

网页首页设有访问码，适合阻止随手打开网页的访客。访问码只在浏览器中校验，公开仓库里的页面数据与 `checked/` 合集直链仍可直接读取，不能用于保密来源内容；影视仓导入链接不需要输入网页访问码。成人直播在客户端使用独立的分组密码；网页不新增成人门禁。

自动抽检的普通／成人标准点播接口仅限 scripts/routes.py 中核对过的 API 主机名单：普通接口要求抽检节目有明确的普通影视分类，成人接口只从公开标记为成人专用的配置和主机收集。直播按来源的 `group-title` 或明确的频道名称分类。标准接口与直播只发布近 36 小时有视频画面抽检通过的线路；按下文模式保留的原配置线路不因此视为实播通过。疑似涉及未成年人的名称不收录。分类检查针对来源元数据和抽样节目，不能过滤影视仓从第三方点播接口读取的整个片库，也不能保证第三方分类永远准确。

从当前成功读取的单配置、多仓和线路合集递归展开，最多 3 层、额外读取 180 个配置。抽取不依赖外部插件、解析器、特殊请求头或账号参数的标准 JSON 点播接口，按 API 去重。每轮最多检测 100 个接口，每接口抽检至多 2 部节目的详情和直连视频画面；至少一部解码成功才发布。抽检器可读取无需登录、公开提供 16 字节密钥的标准 AES-128 HLS 分段，在本机解密后再验证视频画面；只对已核对的公网视频分段主机开放其使用的非标准 HTTPS 端口，其他地址仍按通常端口限制。其他加密方式或无法读取密钥的线路仍不自动收录。标准接口的搜索单独测试，未确认搜索支持的站点仍可浏览。

两条合集地址保持固定，每天随后台检查更新内容。实测不代表整个片库都可用，GitHub 网络和家庭网络可能不同。修改部署仓库时，同步修改 sources.config.json 中 routes.base_url。只上传 HTML 时不包含在线合集文件，两个合集入口需要完整发布包。

## 保留原配置中的搜索线路

`cloud_merge.mode: family` 保留明确指定的 `source_url` 中可搬移的普通、网盘与插件站点、原搜索标记、全局上下文及每站独立 JAR／JS 地址，不复制直播列表。当前采用用户已在电视上使用的小虎斑完整配置；含真实凭据、不可搬移的本地文件依赖或明确成人／高风险标签的站点逐项排除并列出原因。过滤后须至少保留 2 个站点、1 个声明支持搜索的站点，无须另有 2 个网盘站点或独立登录入口。

未设置 `family` 时使用 `selective`：只选择指定来源中的网盘／盘搜站点和登录入口，共用该来源的全局插件；至少需要 2 个网盘相关站点及客户端登录入口。两种模式均要求来源近 36 小时读取成功，不执行插件或验证会员权限。来源失败、快照过期或不符合合入条件时，普通点播仍可发布抽检通过的标准接口。

保留的原站点与补充的标准接口共用 `vod-all.json` 的 `sites` 列表，原标准接口不重复添加。网页的原站点总数是过滤后保留的数量，声明支持搜索数来自配置标记；两者都不是影片结果数，补充接口的抽检结果另列。账号登录按原配置提供的客户端入口完成，后台不读取用户账号文件。

配置可读、插件地址存在和声明支持搜索，都不等于电视实测成功。影视仓会保存同一配置网址下的搜索来源选择，新增站点后请重新选择全部来源，再用同一片名复核。照片中的 `搜索(25/64)` 表示有结果的来源数／参与搜索的来源数，与配置文件的站点总数不同。

小虎斑使用的 `lintech` 公共封装可按影视仓 6.2.5 的格式解码：公开载荷自带的格式标记与 IV，用于还原配置文件，不是会员登录凭据。构建通过系统 OpenSSL 处理这一个明确格式；格式未知、损坏或解码器缺失时仍保留为需客户端验证，不尝试寻找密码。后台不会执行解码结果中的 JAR／JS，也不会读取账号文件。
