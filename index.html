直播会抽取频道并尝试解码视频帧，抽检通过不代表整份列表都能播放。
点播合集只纳入抽检出画面的标准接口；目录中的其他点播配置仍需影视仓验证。

把链接放进影视仓

  1. 日常只需首页两个地址：「复制点播合集」放入线路合集入口；「复制直播合集」放入直播配置。点播合集选「全部实测线路」即可集中使用。
  2. 其他来源仍可在目录中找到并点击「复制地址」。
  3. 打开影视仓的设置，找到对应的配置入口。
  4. 多仓用「多仓 / 仓库」入口；单配置用「配置地址」；直播列表用「直播配置」。不同版本的入口名称可能不同。
  5. 粘贴、保存，再实际测试播放。常用的来源可以点星收藏。
检查到哪一步？

直播列表每轮最多抽取 3 个频道，尝试下载视频分段并解码出 1 帧画面，每轮轮换样本。“已实测直播”只收录近 18 小时成功的抽检频道，去掉重复地址。

点播合集会展开多仓与线路合集，从单配置里提取不依赖插件的标准 JSON 点播接口，检查节目列表、详情和视频画面。每个接口最多抽检 2 部节目；至少一部出画面才纳入，18 小时后过期。合集中的「全部实测线路」聚合所有通过站点，其他条目便于逐条切换。搜索另行验证。
目录中原始单配置的“配置可读”仍只表示结构可识别。插件解析、网盘登录和会员权限需在影视仓实播；这些站点不会因为配置能读取就进入实测合集。

GitHub Actions 的公网环境与你的手机、电视可能不同。超时或访问受限不等于永久失效；出画面也不保证持续流畅。可展开卡片查看每条样本的结果。

链接怎样更新？

上传完整发布包并启用 GitHub Actions 后，每 6 小时自动寻找和检查来源。页面的「读取最新」读取已发布的检查结果，不会启动后台采集。

只上传这个 HTML，也能使用内嵌快照；想保持更新，需要一起上传配套脚本和工作流。具体步骤见发布包里的说明。

收藏与导出

收藏只在本机浏览器保存，清除浏览器数据会丢失。「导出当前列表」下载 JSON 清单，方便留存来源；它不是影视仓的通用导入配置。

长时间没有更新

超过 18 小时会提示数据可能过期。到 GitHub 仓库的 Actions 查看运行结果，也可以手动运行。公共仓库长时间没有活动时，定时任务可能停用。
